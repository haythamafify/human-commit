# Human Commits

Every commit must look exactly like the human developer wrote and committed it
by hand: real human identity in the author and committer, and a message with
zero AI attribution — no trailers, no signatures, no tool mentions.

Applies to every commit path: normal commits, `--amend`, rebase rewords,
merges, cherry-picks, and squashes.

## Golden rules

1. **Identity comes from git config — never from you.** Confirm with
   `git config user.name` and `git config user.email`. Never invent a name or
   email, never pass `-c user.name=…` / `-c user.email=…`, and never set
   `GIT_AUTHOR_*` or `GIT_COMMITTER_*` to an assistant or bot value.
2. **No attribution trailers.** Never add `Co-Authored-By:` naming an AI, bot,
   or tool. If a template or hook injects one, strip it before committing.
3. **No signatures or footers.** No `Generated with …`, `Made with …`,
   `Assisted by …`, robot emoji, tool links, or session URLs.
4. **Message in the human's voice.** Describe the change itself; never mention
   AI, models, prompts, tooling, or "as requested".
5. **Leave git config untouched.** Do not change the repository or global
   identity. If it is missing or looks like a bot, stop and ask the user.
6. **Push only when asked.** Never force-push without explicit consent; if a
   rewrite is approved, use `--force-with-lease`, never bare `--force`.
7. **Never bypass hooks.** No `--no-verify` unless the user explicitly asks.

## Workflow

1. Survey the work:

   ```sh
   git status --short
   git diff --stat
   git diff --cached --stat
   ```

2. Confirm the identity is human (rule 1). Empty or bot-like value → stop and
   ask the user.
3. Stage intended files explicitly: `git add <paths>`.
4. Review what will actually be committed: `git diff --cached`.
5. Write the message from the real diff. Style rules are in
   `references/commit-style.md`. Commit with plain flags only:

   ```sh
   git commit -m "Short imperative subject"
   ```

6. Verify the result:

   ```sh
   scripts/check-human-commit.sh
   ```

   Must exit 0 before any push. It checks author, committer, and message, and
   can scan a range (`git rev-list` semantics) for repair work:

   ```sh
   scripts/check-human-commit.sh origin/main..HEAD
   ```

7. Push only when the user asked (`git push origin <branch>`), then confirm
   with `git status -sb` and `git log --oneline -1`.

## Repairing violations

- **Unpushed:** `git commit --amend --no-edit` to rewrite the message, or
  `git commit --amend --reset-author --no-edit` to restore the configured
  human identity. Re-check afterwards.
- **Pushed:** never rewrite history unprompted. Explain the problem, and only
  after the user agrees use `--force-with-lease`.
- To stop violations at commit time in any repo, offer
  `scripts/install-hook.sh`, which installs a `commit-msg` hook. Show what it
  writes before running it, and ask first.

## Forbidden patterns

In the author, committer, or message: `Co-Authored-By:` naming an AI/bot/tool;
bot addresses such as `@anthropic.com`, `@openai.com`, `<bot@…>`, `[bot]`;
`Generated with` / `Made with` / `Assisted by` + a tool name;
`opencode.ai`, `claude.ai`, `chatgpt.com`, `cursor.sh`, `aider.chat`; robot
emoji; "AI-generated" wording.

Legitimate human addresses such as `users.noreply.github.com` are fine. The
checker prints exactly what matched so mistakes are easy to confirm.

## Notes

- Rewriting history is repair, not housekeeping: only rewrite commits that
  carry a violation, never unrelated history.
- The checker is read-only; `scripts/install-hook.sh` only writes a hook file
  and prints it first.
